# Narrated decks — voiceover with subtitles, synced to slides

## Context

The deck engine is built for a live speaker at the venue. Now that decks also live on
GitHub Pages and in the members' Library, there is no speaker: the reader clicks
through 65 slides in silence. The ask is a recorded human narration that *drives* the
deck like a video — press play, the voice runs, slides advance on cue — with
subtitles in more than one language (Italian + English), for web viewing only.

The hard part the user named is "matching slides to the speaker talking": a person
records one continuous take, and something has to recover where each slide boundary
falls in that recording.

Everything below stays inside the engine's constraints: zero dependencies, runs from
`file://` offline, px inside the canvas, chrome built in JS so no existing deck's
markup has to change.

## The two facts that shape the design

- **Nothing can be fetched from `file://`.** `<track src>` and `fetch()` are both
  blocked (opaque origin in Chrome — silent, no error). Only `<script src>`, `<img>`,
  `<audio>`, `<video>` load. So subtitle and cue data must be **embedded in
  `index.html`** by a script, from `.vtt` source files. `stamp.py` already rewrites
  `index.html` in place, so this is an established ritual, not a new kind of thing.
- **`show()` (`deck.js:68`) is the single choke point** for every slide change and is
  idempotent (line 70 early-returns for the active slide). An audio `timeupdate`
  handler can call `show(n)` on every tick for the cost of one attribute check. It
  fires no event, so the narration module lives inside the same IIFE.

## Data model — one directory per deck

```
2026-08-27-summer-party/
├── narration/
│   ├── audio.m4a       one continuous take. mono AAC 64 kbps ≈ 0.5 MB/min. COMMITTED.
│   ├── slides.vtt      the slide map — one cue per slide boundary
│   ├── en.vtt          subtitles, English
│   └── it.vtt          subtitles, Italian
└── narrate.py          embeds narration/*.vtt into index.html (third helper script)
```

**Why VTT for the slide map too, rather than `data-at` attributes on each
`<section>`:** subtitle editors (Subtitle Edit, Aegisub, even Descript) show the audio
waveform. Nudging a slide boundary is then done in the same tool, against the same
waveform, as the captions — instead of editing timestamps blind in HTML. It also
means the rehearse mode (below) has one output format, and an automatic aligner
(later) has one output format.

`slides.vtt` shape — cue id is the 1-based slide number (the key), cue text is the
`data-label` (for humans; `narrate.py` warns when it no longer matches, which is how
you notice a reorder invalidated the timings):

```
WEBVTT

1
00:00:00.000 --> 00:00:14.200
Cover

2
00:00:14.200 --> 00:00:41.900
Tonight's schedule
```

Slides absent from `slides.vtt` are not part of the narrated run (bio photo streams,
say). Reaching one manually while narration plays **pauses** the narration — the
alternative, letting `timeupdate` yank the reader back, is worse.

**Audio is committed — a documented exception to "video is never committed".** The
narration *is* the web deliverable, and CI has to be able to build it (it is ~7 MB for
a 15-minute take, against 24 MB of photography already in the repo). A gitignore
negation `!*/media/narration*` was considered and rejected: a separate `narration/`
directory keeps the exception visible instead of buried in a negation rule.

**SRT is accepted, VTT is canonical.** The parser reads both (`,` vs `.` in
timestamps is the only real difference); `narrate.py` normalises SRT to VTT text on
embed. Author in whichever your tool produces.

## Engine behaviour (deck.js + deck.css, `_template/` then copied forward)

**Markup** — one element, in the chrome section of `index.html`, outside `#canvas`
(inside a slide it would be cloned 65× by `buildOverview()` `deck.js:222` and torn
down by the leave-slide logic at `deck.js:76`):

```html
<audio id="narration" src="narration/audio.m4a" preload="metadata"></audio>
<!-- narration:begin --> … generated by narrate.py … <!-- narration:end -->
```

The generated block is `<script type="text/vtt" data-track="slides">`,
`<script type="text/vtt" data-track="en" data-name="English">`, etc. Browsers ignore
unknown script types, so the text is inert until `deck.js` reads `.textContent`. The
web build needs no change for these — they are already inline.

**Boot:** if `#narration` is absent, nothing below exists — every existing deck is
unchanged. If present, a ~30-line VTT parser reads the embedded tracks into arrays of
`{start, end, text}` (skip `NOTE`/`STYLE`/`REGION` blocks, ignore cue settings after
the arrow, allow only `<b><i><u>` in text). Then build two chrome elements in JS, on
the `#turn` pattern (`deck.js:39-53`, `deck.css:396-406`):

- **`#narrate`** — a bottom-left pill: play/pause glyph, elapsed / total, thin
  progress. Required because browsers block audio without a gesture, and because a
  reader who tapped a link has no idea `V` exists. Shown only when the audio element
  reports it can load (`loadedmetadata`); a failed load shows "Narration not found",
  mirroring `data-video-missing`.
- **`#captions`** — the subtitle bar, bottom-centre, **in chrome, not in the canvas.**
  Inside the canvas it would scale with the slide and become 7px on a phone; in chrome
  it stays legible, and on a letterboxed phone it sits in the black below the slide.
  On the Library's 16:9 iframe it overlays the slide's bottom edge like any video
  player's captions. z-index 65: above nav zones (55), below `#blank` (80) so `B` still
  covers it. Exempt from the `body.idle` fade — narration plays precisely when nobody
  is touching anything.

**Sync — the core loop:**

- `audio.timeupdate` → find the last `slides.vtt` cue with `start <= currentTime` →
  `show(cueId - 1, { from: 'narration' })`. New option; `show()` gains one branch.
- Any `show()` call *without* `from:'narration'` while narration is loaded → seek
  `audio.currentTime` to that slide's cue start (if it has one; else pause, above).
  This is what makes `→`, click zones, swipe, the overview grid and `#7` deep links
  all "scrub" the narration for free.
- Pressing play on slide *n* seeks to *n*'s cue first, so a reader who opened `#12`
  hears slide 12, not the cover.
- Captions: on `timeupdate`, active cue of the selected language → `#captions`
  text; none → hidden. `C` cycles off → en → it → off; default language picks the
  first track whose code matches `navigator.language`, else the first track.
- `ended` → leave the last slide up, clear captions, pill shows replay.

**Pause rules** (the video convention at `deck.js:72-73` says a talk track running
under the wrong picture is the worst failure):

| Event | Narration |
|---|---|
| `B`/`W` blank | pause; resume on unblank if it was playing (`clearOverlays()` `deck.js:206` is the single hook) |
| `O` overview, `?` help | pause; resume on close if it was playing |
| manual nav to an un-narrated slide | pause |
| `V` / pill / Space while narration loaded | toggle — Space mirrors the video rule at `deck.js:289`: it pauses instead of advancing |
| video slide reached during narration | moot for web — `build-web-deck.mjs:59` drops every video slide. Document: narrated decks and autoplay-with-sound video don't mix at the venue |

**Keys** — `V` narration play/pause, `C` captions cycle, `R` rehearse (below). All
three unused today. Each needs an explicit `case` in the switch (`deck.js:296-315`)
— the `default` branch `return`s before `preventDefault`. Add rows to the help table
in both `index.html`s. Decide deliberately that `V` while blanked unblanks (the
any-key rule at `deck.js:280`) rather than toggling audio — keep the rule.

**CSS**: `#narrate`, `#captions` styles; add both ids to the print suppression list
(`deck.css:526`); `prefers-reduced-motion` needs no change (auto-advance is
user-initiated by pressing play).

## Recovering the slide boundaries — "matching slides to the speaker"

Three tiers, cheapest first. The first is enough to ship.

### Tier 1 — Rehearse mode in the deck (`R`), zero dependencies

Load the deck with `audio.m4a` in place and an empty or stale `slides.vtt`. Press `R`:
audio plays from the top with captions off, the pill turns red, and every slide change
the presenter makes by hand logs `(slide, audio.currentTime)`. Press `R` again (or let
the audio end) and the engine assembles a complete `slides.vtt` — each cue running
from its slide's timestamp to the next — and offers it as a download
(`<a download>` works from `file://`). Drop it into `narration/`, run `narrate.py`,
done. Nudge any boundary in a subtitle editor against the waveform.

This is Keynote's "Record Slideshow" with the recording step removed: you listen to
the take and press `→` when the speaker moves on. Ten minutes of work for a
fifteen-minute deck, and it exercises exactly the sync code the reader will use.

### Tier 2 — Subtitles from the recording (external, one-off)

Run Whisper (local: `whisper.cpp` or `faster-whisper`; or any hosted transcription)
on `audio.m4a` → `en.vtt` or `it.vtt` in one step; these tools emit VTT/SRT natively
with sentence-level timing. Translate to the second language preserving cue timings
(DeepL or an LLM pass over cue text only). Neither touches the repo — they are
workflow, documented in `SKILL.md`, not code.

### Tier 3 — Automatic slide alignment (`scripts/align-narration.py`, later)

Build-tooling tier like `sharp`, never a deck dependency. Takes the Whisper transcript
with word timestamps plus the per-slide text from `extract-copy.py` run with
`EXCLUDE = r'^$'` (headings, eyebrows, first bullets — the words a speaker actually
says aloud), and finds a monotonic assignment of slides to transcript positions
(token-overlap score per slide against a sliding window, dynamic programming to
enforce order). Emits a *draft* `slides.vtt` to review in rehearse mode. Worth
building once there are three narrated decks and the rehearse pass has become the
bottleneck; not before.

## Build and deploy

- `scripts/build-web-deck.mjs`: add `'.m4a': 'audio/mp4'` (and `.mp3`) to `MIME`
  (`:42`) — media elements don't content-sniff, so the current
  `application/octet-stream` fallback yields silent audio. `assetRefs` (`:83`) already
  picks up `<audio src>`. When `narration/audio.m4a` is absent (a clone without it,
  or a deck with no narration), strip the `<audio>` element the way `dropMissingFaces`
  (`:73`) strips fonts, so the un-inlined guard (`:171`) doesn't fail the build.
  Inlined audio adds ~33%: a 7 MB take → 9.5 MB, whole deck ~16 MB in one file. If
  that ever hurts the Library, the alternative is a sidecar `narration/audio.m4a`
  next to the built HTML for Pages only — noted, not built.
- `stamp.py`: no change needed. The VTTs are embedded, and the audio filename is
  stable; if a re-recorded take under the same name ever bites, extend the
  alternation at `stamp.py:24` to cover `narration/`.
- `pages.yml`: no change — audio is committed, so CI has it.
- `_template/narration/.gitkeep` so `cp -R` yields the directory, matching `media/`.

## Order of work

1. Data model + `narrate.py` + markup markers. Hand-write a 4-cue `slides.vtt` and a
   6-cue `en.vtt` against any short audio file to develop against.
2. Engine: parser → captions bar → play control → sync → pause rules → keys.
3. Rehearse mode.
4. Build script + docs. Commit, push; Pages deploys.
5. Real content: someone records the summer party take; Whisper → `en.vtt`;
   translate → `it.vtt`; rehearse → `slides.vtt`.

## Verification

- **Unit-ish, in the browser via `javascript_tool`** on the local `http.server` copy,
  the way the horizontal-nav change was verified: dispatch `timeupdate` after setting
  `audio.currentTime` and assert `#counter`; call `show(n)` and assert
  `audio.currentTime` seeks; toggle `blanked`/`overview` and assert `audio.paused`;
  press `C` and assert `#captions` text and language cycling; parse a VTT and an SRT
  with `NOTE` blocks, cue settings, and `<v>` tags and compare cue arrays.
- **Real playback** in Chrome and Safari from `file://` (data URI audio in Safari is
  the one to watch) and from the Pages URL on a phone: pill visible, captions legible
  in the letterbox, swipe scrubs audio.
- **Build**: `npm run web:build` with and without `narration/audio.m4a` present;
  the output must pass the un-inlined guard both ways and play when present.
- **Rehearse round-trip**: press `R`, step through, download, `narrate.py`, reload,
  play — slides land where they were pressed.

## Considered and set aside

- **`<track>` elements** — blocked from `file://`; also reject anything but
  `text/vtt` and behave inconsistently with `data:` URIs. Embedding + own parser is
  ~30 lines and removes every one of those failure modes.
- **`data-at` on each `<section>`** — in the markup idiom, but edited blind; the
  waveform argument wins for `slides.vtt`.
- **Per-slide clips instead of one take** — no sync problem, but no continuous
  performance, a gap at every slide, and N files to manage. User chose one take.
- **Recording inside the deck with `MediaRecorder`** — appealing (timings and audio
  on one clock) but drags in mic permissions from `file://`, WebM/Opus vs Safari, and
  a recording UI. Any voice-memo app plus rehearse mode gets the same result.
- **Subtitles inside the canvas** — consistent with the engine, unreadable on phones.
- **TTS** — sync would be free by construction (one clip per slide, boundaries
  known). Not the user's case now, but the `narration/` layout accepts a TTS take
  with no change.
